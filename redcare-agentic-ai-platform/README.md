# Redcare Agentic AI Platform

A working reference implementation of the platform described in the **Product Manager,
Agentic AI Platform** role: Azure Cloud, LiteLLM/AI gateway administration, Terraform,
GitHub Actions, observability tooling, MLOps/LLMOps, security and developer experience —
built as one system rather than described as a list.

Everything here runs. The agent answers questions, the router really fails over, the
guardrails really block, the evals really gate, and the Terraform really describes the
Azure estate it claims to.

---

## Start here — nothing to install

Open **[`apps/playground-standalone/console.html`](apps/playground-standalone/console.html)**
in any browser. The whole platform runs client-side: the agent loop, the gateway
routing, the guardrails, the approval flow and the eval suite. No install, no server,
no API key, no network call.

Run the real service instead — the thing that would actually deploy to Azure:

```bash
cd apps/agent-service
pip install -r requirements.txt
uvicorn app.main:api --port 8080     # then open http://localhost:8080
```

It defaults to `LLM_MODE=mock`, a deterministic in-process model that exercises the
entire loop with no credentials and no cost. Set `LLM_MODE=litellm` to route through
the real gateway.

The whole stack, including a real LiteLLM proxy, Prometheus and Grafana:

```bash
docker compose --profile gateway up      # agent :8080 · gateway :4000
                                          # prometheus :9090 · grafana :3000
```

## The technology, and the job each piece does

| Technology | Its job here |
|---|---|
| **Azure Container Apps** | Runs the agents and the gateway. Revisions, traffic splitting, KEDA autoscaling, managed identity — without operating Kubernetes. |
| **Azure OpenAI** (2 EU regions) | The models. Second region is failover *and* a second quota pool. |
| **LiteLLM** | The only path to a model. Virtual keys, entitlement, rate limits, budgets, failover, semantic cache, cost attribution, guardrail hooks. |
| **Terraform** | Every Azure resource, reviewed as a plan diff, applied only by the pipeline. |
| **GitHub Actions** | The only path to production. Eval gate, plan-on-PR, OIDC apply, signed images, canary release. |
| **OpenTelemetry + Azure Monitor + Grafana** | Four signal families: RED, agent behaviour, quality, FinOps. |
| **Azure Key Vault + Entra ID** | No long-lived secret exists anywhere in the chain. |
| **Azure AI Search** | Hybrid retrieval for the policy corpus behind grounded answers. |
| **OPA / Conftest, Checkov, Trivy, cosign** | Policy and supply chain, enforced in the pipeline. |

## A note on what this is

This is a **teaching instrument as much as a system**. Most platform artefacts hide
their reasoning: you see a config value, not the argument for it. Here the trace shows
*why* a model was chosen, the tool cards show *what* an agent may touch, the policies
carry the reason they exist in the failure message, and the code comments explain the
tradeoff rather than restating the line below them.

That is deliberate, and it is the same discipline the role itself asks for: turning
complex platform engineering into decisions other people can understand, argue with,
and act on.
